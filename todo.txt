## Unsigned comparisons

There is no single instruction for >= for specifically unsigned char!
For unsigned, there is only

seta - set if above (>)
setb - set if below (<)

In order to implement a >= b, make it b < a which is available using setb!


```
// sete / setz      — Set if equal / set if zero
// setne / setnz    — Set if not equal / set if not zero
//
// --------------------------- signed ----------------------------
// setg / setnle    — Set if greater (signed)
// setge / setnl    — Set if greater or equal (signed)
// setl / setnge    — Set if less (signed)
// setle / setng    — Set if less or equal (signed)
//
// --------------------------- unsigned --------------------------
// seta / setnbe    — Set if above (unsigned)
// setb / setC      — Set if below / set if carry (unsigned)
```

## Character '°' kills the lexer

I am not sure what i happening, but if the lexer looks up transitions
for the '°' character, then the call enters the Rust-HashMap and never returns!
Either the Rust HashMap is buggy or there is a problem with the lexer!

These inputs kills it:

```
// (0°C 9/5) + 32
/* (0°C 9/5) + 32 */
// (0 ° C 9/5) + 32
/* (0 ° C 9/5) + 32 */
```

The ° character is used in a single line comment

Full source code:

```
//#include <stdio.h>

/* Print Fahrenheit-Celsius table for fahr = 0,20,...,300 */

int main()
{
    //float fahr, celsius;
    //float lower, upper, step;

    //int fahr, celsius;
    //int lower, upper, step;

    int fahr;
    int celsius;
    int lower;
    int upper;
    int step;

    lower = 0;   // Lower limit of temperature scale
    upper = 300; // Upper Limit
    step = 20;   // Step size

    celsius = lower;

    //printf("Celsius\tFahrenheit\n");

    while (celsius <= upper) {

        // (0°C 9/5) + 32

        //fahr = (celsius * (9.0 / 5.0)) + 32;

        fahr = (celsius * (9 / 5)) + 32;

        return fahr;

        //printf("%8.0f %10.2f\n", celsius, fahr);

        celsius = celsius + step;
    }

    return 17;
}
```
